# Лабораторная работа №4: контейнеризация MusicStore

## Состав решения

`Dockerfile` собирает API в два этапа с закреплёнными версиями .NET SDK и
ASP.NET Runtime. Зависимости NuGet зафиксированы в `packages.lock.json`; при
сборке используется `--locked-mode`. Контекст сборки ограничен `.dockerignore`.
Приложение работает от UID/GID 1000, с файловой системой только для чтения,
без дополнительных Linux capabilities. Проверка состояния обращается к API и
базе данных. Для остановки предусмотрено 15 секунд.

`compose.yaml` запускает PostgreSQL, миграции и API. База и миграции доступны
только во внутренней сети. Снаружи открыт лишь порт 8080 приложения. Данные
PostgreSQL находятся в именованном томе. Пароли базы и ключ JWT хранятся в
локальных файлах `secrets/`, передаваемых контейнерам как Compose secrets.
Эти файлы исключены из Git и из контекста сборки. Для сервиса восстановления
используется отдельный том `restore_data`.

## Запуск на Linux

Установите Docker Engine с Compose plugin, Python 3, OpenSSL, curl и Make.
Из корня проекта выполните:

```bash
make container-setup
make container-check
```

Проверка сначала анализирует Compose и Dockerfile: закреплённые версии
образов, пользователя приложения, секреты, сети, порты, ограничения ресурсов и
healthcheck. Только после этого она собирает образ и меняет окружение. Затем
она проверяет запуск, пользователя процесса, ответ API, сохранность записи
после пересоздания контейнеров, резервное копирование, восстановление в
отдельный том и корректную остановку приложения.

Для обычного запуска и остановки:

```bash
make container-up
make container-down
```

`container-down` сохраняет именованные тома. Запускайте проверку на отдельном
учебном окружении: она добавляет таблицу `lab4_persistence_probe` и создаёт
резервную копию в `backups/`. Файлы секретов и резервных копий в Git не
попадают. Порт 8080 должен быть свободен.

Для просмотра состояния:

```bash
docker compose ps
curl -fsS http://127.0.0.1:8080/api/health
docker compose exec -T app id
```

## Проверка на MusicStore-App

ВМ работает под Debian 13. Проверка выполнялась на самой Linux ВМ, а не в
Windows. Скриншоты консоли сохранены отдельно в папке лабораторной работы
`Скриншоты`. Результаты запуска и ограничения приведены в этих снимках и в
выводе `make container-check`.

20.11.2026 на `MusicStore-App` проверка завершилась строкой `Container check
passed`. Docker Engine — 29.10.0, Compose — 5.8.0. API и обе базы имели
состояние `healthy`; API работал от UID 1000 и отвечал на `/api/health`.
Контрольная запись осталась после пересоздания контейнеров и появилась в
восстановленной базе на отдельном томе. Приложение остановилось с кодом 0 и
после повторного запуска вернулось в здоровое состояние. На Windows также
прошли форматирование и все 19 тестов .NET.
