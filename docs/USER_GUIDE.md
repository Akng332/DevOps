# MusicStore — полная инструкция по использованию

MusicStore — учебный музыкальный магазин на ASP.NET Core и PostgreSQL. В проект входят веб-интерфейс, HTTP API, база данных, миграции, контейнерное окружение, автоматические проверки и отдельный staging-стенд. Этот документ относится к ветке `lab6/cd`.

## Что входит в продукт

| Часть | Назначение |
| --- | --- |
| Веб-интерфейс | Просмотр альбомов, регистрация, вход, корзина, покупка, личный кабинет. Для администратора — добавление, изменение и удаление альбомов. |
| HTTP API | Те же основные операции, а также получение списка товаров с низким остатком и всех продаж для администратора. |
| PostgreSQL 17 | Хранит пользователей, альбомы, музыкантов, произведения, продажи и остатки. |
| Миграции | Последовательно создают и обновляют схему базы. Приложение не меняет схему при старте. |
| Docker Compose | Запускает приложение, БД и мигратор; том БД сохраняет данные после пересоздания контейнеров. |
| GitHub Actions | Проверяет форматирование, тесты, БД, безопасность и контейнер, затем публикует образ с SHA-тегом. |
| Staging | Отдельный стенд на `MusicStore-App`, который скачивает прошедший CI образ, проверяет его и откатывает неудачный релиз. |

Адрес зависит от способа запуска:

| Режим | Адрес веб-интерфейса и API |
| --- | --- |
| Локальный запуск .NET с профилем `http` | `http://localhost:5058` |
| Основное контейнерное окружение на ВМ | `http://192.168.56.10:8080` |
| Staging на ВМ | `http://192.168.56.10:18080` |

Адреса `192.168.56.10` работают с компьютера, подключённого к учебной сети VirtualBox Host-only. Staging — место проверки релиза, а не отдельный публичный магазин.

## Быстрый вход для пользователя

1. Откройте адрес работающего окружения из таблицы выше. Каталог доступен без регистрации.
2. Нажмите **Войти**, затем выберите **Регистрация** для создания обычной учётной записи. После регистрации приложение сразу выдаёт токен и открывает каталог.
3. Откройте карточку альбома, посмотрите цену и остаток. Если товар есть в наличии, нажмите **В корзину**.
4. Откройте **Профиль**. Там находятся корзина, итоговая сумма, кнопки **Оформить покупку** и **Очистить**, а также история ваших покупок.
5. После оформления магазин уменьшит остаток и добавит записи о покупке. Если запрошено больше товара, чем осталось, операция завершится ошибкой без частичной покупки.

Кнопка **Выйти** удаляет токен входа из браузера. Корзина хранится в `localStorage` этого браузера и при выходе автоматически не очищается; при необходимости используйте **Очистить**.

## Работа в веб-интерфейсе

### Каталог и карточка альбома

Главная страница показывает обложку, название, автора, цену и остаток. Нажатие на карточку открывает подробное окно. При нулевом остатке кнопка покупки недоступна. По умолчанию в пустую базу при первом старте добавляются шесть демонстрационных альбомов.

Каталог можно просматривать без входа. Для покупки требуется обычная учётная запись или учётная запись с доступом к API покупки. В текущем интерфейсе администратор управляет каталогом; кнопка **В корзину** для него не отображается.

### Регистрация, вход и профиль

На странице **Войти** есть две вкладки: **Вход** и **Регистрация**. Логин должен быть свободен. После входа ссылка **Профиль** показывает ID, логин, роль и дату регистрации. Токен JWT сохраняется в `localStorage` браузера; срок его действия задаётся `Jwt__ExpiresInHours` и в текущей конфигурации равен 24 часам. При истечении токена войдите снова.

Новые пользователи получают роль `user`. Самостоятельно выдать себе роль `admin` через регистрацию нельзя.

### Корзина и покупка

На карточке альбома нажмите **В корзину**. В профиле можно удалить отдельную позицию, очистить всю корзину или оформить покупку. Количество одинакового товара увеличивается при повторном добавлении. Перед подтверждением сервер ещё раз проверяет наличие всех позиций; сумма рассчитывается по актуальным ценам на сервере. История в профиле показывает только покупки текущего пользователя.

В приложении нет подключения к платёжной системе: «оформить покупку» означает записать учебную продажу в базу и уменьшить остаток.

### Администрирование каталога

Учётная запись с ролью `admin` видит кнопку **+ Добавить альбом** и кнопки изменения и удаления на карточках. При добавлении укажите название, автора, ссылку на обложку, цену и количество. При изменении можно скорректировать эти поля. Цена должна быть больше нуля, количество и порог остатка — неотрицательными. Удаление требует подтверждения в браузере.

Первый администратор создаётся только при настройке приложения через `BootstrapAdmin__Username` и `BootstrapAdmin__Password` (пароль не короче 16 символов). Эти значения нужны на **первом** запуске и затем должны быть удалены из окружения. Не добавляйте их в Git, Dockerfile или постоянный Compose-файл. Детальная настройка для локального запуска есть ниже и в [README](../README.md).

Список товаров с низким остатком и список продаж всех пользователей доступны администратору через API. Отдельных экранов для них в текущем веб-интерфейсе нет.

## Роли и возможности API

Базовый адрес API — адрес выбранного окружения плюс `/api`. В запросах с пометкой `user` или `admin` передавайте заголовок `Authorization: Bearer <JWT>`.

| Метод и путь | Доступ | Результат |
| --- | --- | --- |
| `GET /api/health` | Любой | Состояние API и соединения с БД (`Healthy` или HTTP 503). |
| `GET /version` | Любой | SHA работающего образа; для локальной сборки без SHA возвращается `dev`. |
| `GET /api/discs` | Любой | Каталог альбомов. |
| `GET /api/discs/{id}` | Любой | Один альбом или HTTP 404. |
| `POST /api/auth/register` | Любой | Создаёт обычного пользователя и возвращает токен. |
| `POST /api/auth/login` | Любой | Проверяет пароль и возвращает токен. |
| `GET /api/auth/me` | `user` или `admin` | Данные текущей учётной записи. |
| `POST /api/sales/checkout` | `user` или `admin` | Покупка товаров из массива `{discId, quantity}`. |
| `GET /api/sales/my` | `user` или `admin` | История собственных покупок. |
| `GET /api/sales/all` | `admin` | Все продажи. |
| `GET /api/discs/low-stock` | `admin` | Альбомы, где остаток не выше порога. |
| `POST /api/discs` | `admin` | Создание альбома. |
| `PUT /api/discs/{id}` | `admin` | Изменение альбома. |
| `DELETE /api/discs/{id}` | `admin` | Удаление альбома. |

Пример для PowerShell. Подставьте адрес своего окружения; пароль запрашивается скрытым вводом и не записывается в команду:

```powershell
$base = 'http://localhost:5058'
$secure = Read-Host 'Пароль MusicStore' -AsSecureString
$password = [System.Net.NetworkCredential]::new('', $secure).Password
$login = Invoke-RestMethod -Uri "$base/api/auth/login" -Method Post `
  -ContentType 'application/json' `
  -Body (@{ username = 'мой_логин'; password = $password } | ConvertTo-Json)
$password = $null
$headers = @{ Authorization = "Bearer $($login.token)" }
Invoke-RestMethod -Uri "$base/api/auth/me" -Headers $headers
Invoke-RestMethod -Uri "$base/api/sales/my" -Headers $headers
```

Пример оформления одной единицы диска с ID `1`:

```powershell
$items = @(@{ discId = 1; quantity = 1 }) | ConvertTo-Json -AsArray
Invoke-RestMethod -Uri "$base/api/sales/checkout" -Method Post `
  -Headers $headers -ContentType 'application/json' -Body $items
```

В режиме `Development` документация Swagger открывается по `/swagger`. В `Production` она в текущем коде отключена.

## Запуск на своём компьютере

### Подготовка

Понадобятся Git, .NET SDK **10.0.404** и PostgreSQL **17.x** с утилитами `psql`, `pg_dump`, `pg_restore`. Точная версия SDK закреплена в `global.json`. На Windows для команд `bash` и `make` нужен подходящий Unix-терминал; основные команды `.NET` ниже выполняются в PowerShell.

```powershell
git clone https://github.com/Akng332/DevOps.git
cd DevOps
git switch lab6/cd
dotnet --version
psql --version
```

Создайте БД, роль владельца схемы `musicstore_migrator` и отдельную роль приложения `musicstore_app`. Примените миграции `database/migrations` от администратора PostgreSQL, затем выдайте `musicstore_app` права на чтение и изменение данных. Готовые команды и права перечислены в [README](../README.md#подготовить-postgresql) и [описании миграций](../database/README.md). Схему нельзя создавать от имени обычного пользователя приложения.

### Настройка и первый запуск

Задайте в **текущей** PowerShell-сессии строку подключения и ключ JWT. Конфигурацию из `appsettings.json` можно переопределять переменными окружения; в файле по умолчанию указан адрес учебной ВМ БД, поэтому для локальной БД переопределение обязательно.

```powershell
$dbSecret = Read-Host 'Пароль musicstore_app' -AsSecureString
$dbPassword = [System.Net.NetworkCredential]::new('', $dbSecret).Password
$env:ConnectionStrings__Default = "Host=localhost;Port=5432;Database=musicstore;Username=musicstore_app;Password=$dbPassword"
$dbPassword = $null
$keyBytes = New-Object byte[] 32
[System.Security.Cryptography.RandomNumberGenerator]::Fill($keyBytes)
$env:Jwt__Key = [Convert]::ToBase64String($keyBytes)
$env:Jwt__Issuer = 'MusicStoreApi'
$env:Jwt__Audience = 'MusicStoreClient'
$env:ASPNETCORE_ENVIRONMENT = 'Development'
```

При необходимости добавьте первого администратора **до первого запуска**:

```powershell
$adminSecret = Read-Host 'Пароль первого администратора, минимум 16 символов' -AsSecureString
$env:BootstrapAdmin__Username = 'admin'
$env:BootstrapAdmin__Password = [System.Net.NetworkCredential]::new('', $adminSecret).Password
```

Запустите приложение из корня репозитория:

```powershell
dotnet restore .\MusicStore.sln --locked-mode
dotnet run --project .\src\MusicStore.Api\MusicStore.Api.csproj --launch-profile http
```

Откройте `http://localhost:5058`. После первого успешного старта остановите процесс `Ctrl+C`, удалите одноразовые переменные администратора и запустите снова:

```powershell
Remove-Item Env:BootstrapAdmin__Username, Env:BootstrapAdmin__Password -ErrorAction SilentlyContinue
dotnet run --project .\src\MusicStore.Api\MusicStore.Api.csproj --launch-profile http
```

Проверка в другом окне PowerShell:

```powershell
Invoke-RestMethod http://localhost:5058/api/health
Invoke-RestMethod http://localhost:5058/version
Invoke-RestMethod http://localhost:5058/api/discs
```

Файл `.env` приложение само не загружает. Пример состава настроек — [`.env.example`](../.env.example); настоящие пароли в репозиторий не добавляют.

## Запуск в Docker Compose

Из корня репозитория на машине с Docker Engine и Compose:

```bash
bash scripts/container-setup.sh
docker compose up -d --build db migrator app
docker compose ps
curl -fsS http://127.0.0.1:8080/api/health
```

`container-setup.sh` создаёт каталог `secrets/` и три файла: пароль администратора PostgreSQL, пароль приложения к БД и ключ JWT. Каталог исключён из Git. Compose создаёт отдельный том `musicstore-lab4_db_data`. Сначала запускается БД, затем мигратор, после него API. Веб-интерфейс открывается на порту `8080` хоста Docker. Если Docker запущен на `MusicStore-App`, используйте `http://192.168.56.10:8080`.

Полная проверка контейнерного окружения:

```bash
make container-check
```

Она собирает образ, проверяет состояние приложения и БД, сохранение данных после пересоздания, резервное копирование и восстановление в отдельном томе. Это проверка с изменением тестовых данных; для повседневного запуска достаточно `docker compose up -d --build db migrator app`.

Полезные команды:

```bash
docker compose ps
docker compose logs --tail=100 app
docker compose logs --tail=100 db migrator
docker compose restart app
docker compose down
```

`docker compose down` останавливает и удаляет контейнеры, сохраняя именованный том БД. Удаление тома приводит к потере данных, поэтому перед очисткой окружения проверьте резервную копию.

В контейнерном запуске администратор **не создаётся автоматически**, если одноразовые `BootstrapAdmin__Username` и `BootstrapAdmin__Password` не переданы приложению при первом старте. Задавайте их только на время начальной настройки сервера и удаляйте после создания учётной записи. Обычная регистрация создаёт только роль `user`.

## База данных и резервные копии

Миграции `001`–`004` применяются по порядку. Таблица `schema_migrations` фиксирует выполненные версии, поэтому повторный запуск пропускает их. Для изменения схемы нужна учётная запись с правом `SET ROLE musicstore_migrator`; runtime-роль `musicstore_app` этого делать не должна.

Для Compose резервную копию можно сохранить в локальный каталог `backups/`:

```bash
mkdir -p backups
docker compose --profile tools run --rm db-tools \
  /scripts/container-backup.sh /backups/musicstore-manual.dump
```

Проверяйте восстановление в **отдельной** тестовой базе или отдельном томе, прежде чем заменять действующие данные. Сценарий `make container-check` делает именно такую проверку через сервис `restore-db`. Самостоятельное восстановление непосредственно в рабочую БД может удалить или перезаписать записи; порядок и параметры описаны в [scripts/restore.sh](../scripts/restore.sh) и [ЛР 3](lab3.md).

## Проверки, публикация и staging

Ветка `lab6/cd` настроена на GitHub Actions. При push последовательно проходят форматирование и тесты, отдельная проверка миграций и восстановления, Semgrep/Trivy, контейнерный сценарий и сканирование образа. Только после успеха всех этапов публикуется `ghcr.io/akng332/devops:sha-<полный SHA коммита>`. Для pull request публикации нет. Журналы и отчёты доступны как артефакты запуска в разделе **Actions** репозитория.

Staging на `MusicStore-App` расположен в `/opt/musicstore-staging`. Он использует собственную БД и порт `192.168.56.10:18080`, не пересобирает код на сервере. Учётная запись `musicstore-deploy` раз в три минуты смотрит последний push-run ветки `lab6/cd`. Когда run успешно завершён, она скачивает образ с соответствующим SHA и проверяет здоровье контейнера, `/api/health`, `/version` и чтение `/api/discs`. Если проверка не прошла, возвращается предыдущий рабочий образ. Подробности — в [ЛР 5](lab5.md) и [ЛР 6](lab6.md).

Проверить текущий staging-релиз с Windows:

```powershell
Invoke-RestMethod http://192.168.56.10:18080/api/health
Invoke-RestMethod http://192.168.56.10:18080/version
Invoke-RestMethod http://192.168.56.10:18080/api/discs
```

Проверить окружение на самой ВМ:

```bash
cd /opt/musicstore-staging
docker compose ps
cat .last-good-image
tail -n 100 deploy.log
crontab -l
```

Для `docker compose` в этом каталоге задайте `IMAGE_REF` равным текущему тегу из `.last-good-image`, например `IMAGE_REF="$(cat .last-good-image)" docker compose ps`. Ручной выпуск конкретного опубликованного тега выполняется командой `bash /opt/musicstore-staging/deploy.sh ghcr.io/akng332/devops:sha-<полный SHA>`. Перед ручным откатом проверьте совместимость миграций: автоматический откат меняет образ приложения, но не откатывает схему и данные PostgreSQL.

## Диагностика

| Признак | Что проверить |
| --- | --- |
| Страница не открывается | Адрес и порт, `docker compose ps`, состояние ВМ и сеть Host-only, firewall. Локальный .NET использует 5058, основной Compose — 8080, staging — 18080. |
| `/api/health` возвращает 503 | Доступность PostgreSQL, параметры подключения, журнал `db` и `app`. |
| Контейнер `migrator` завершился с ошибкой | `docker compose logs migrator`, создан ли каталог `secrets/`, есть ли права мигратора и не нарушены ли ограничения данных. |
| Вход не работает | Правильность логина и пароля; для уже вошедшего пользователя — срок токена. После истечения войдите снова. |
| В корзине есть товары, но покупка не проходит | Войдите в аккаунт, обновите каталог, проверьте остаток. Сервер отклоняет покупку при недостатке хотя бы одной позиции. |
| Админские кнопки не видны | Проверьте роль в **Профиле** или через `/api/auth/me`. Регистрация выдаёт роль `user`. |
| Новый релиз не появился в staging | Убедитесь, что последний push-run `lab6/cd` завершился успешно, образ опубликован, `crontab -l` содержит `poll.sh`, а в `deploy.log` нет ошибки скачивания или smoke-проверки. |
| `/version` показывает прежний SHA | Развёртывание ещё не завершилось либо новый релиз был откатан. Сравните `/version`, `.last-good-image` и журнал доставки. |

## Правила безопасности и ограничения

- Не размещайте реальные пароли, JWT-ключи, `.env` и содержимое `secrets/` в Git. Для API используйте HTTPS при работе за пределами изолированной учебной сети.
- Не сообщайте токен JWT другим людям. Веб-интерфейс хранит его в `localStorage` браузера; на общем компьютере после работы нажмите **Выйти** и при необходимости очистите данные сайта.
- Не используйте демонстрационные данные как рабочую БД. Учебная покупка не принимает реальный платёж.
- Самостоятельная регистрация администратора, восстановление пароля, поиск по каталогу и экран всех продаж в текущем веб-интерфейсе отсутствуют. Администратора создаёт оператор при настройке; все продажи и низкие остатки доступны через API с ролью `admin`.
- Файл `.github/CODEOWNERS` отмечает критические файлы, но обязательное ревью начнёт действовать только после включения защиты ветки и соответствующего правила в настройках GitHub.

Исходные инструкции по развёртыванию на двух Debian-ВМ находятся в [docs/virtualbox-deployment.md](virtualbox-deployment.md). Правила изменений проекта — в [CONTRIBUTING.md](../CONTRIBUTING.md).
