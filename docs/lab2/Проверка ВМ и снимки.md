# ЛР2. Развертывание приложения в Linux

Проверка выполнена 20 ноября 2026 года на двух ВМ Debian 13: `MusicStore-App`
(`192.168.56.10`) и `MusicStore-DB` (`192.168.56.11`). Вторые сетевые адаптеры
подключены к Host-only сети VirtualBox `192.168.56.0/24`, как указано в
инструкции. После перезагрузки адреса сохранились.

## Firewall

На обеих ВМ включён UFW с политикой `deny incoming` и `allow outgoing`.

- `MusicStore-DB`: SSH разрешён с `192.168.56.1`; PostgreSQL `5432/tcp` —
  только с `192.168.56.10`.
- `MusicStore-App`: SSH и веб-порт `8080/tcp` разрешены с `192.168.56.1`.
  Также разрешён источник `10.0.2.2` на портах 22 и 8080 для локальных
  перенаправлений VirtualBox, привязанных на хосте к `127.0.0.1`.
- На приложении удалены обнаруженные ранее широкие правила SSH.

Проверки после включения правил: веб-порт приложения доступен и `/api/health`
возвращает `Healthy`; SSH доступен с хоста; API приложения успешно получает
список дисков из PostgreSQL; TCP/5432 с хоста закрыт, а подключение с ВМ
приложения к БД проходит.

## PostgreSQL

Роли `musicstore_app` и `musicstore_migrator` не являются superuser и не имеют
права создавать базы данных. Для `musicstore_app` проверены права `CONNECT`
к `musicstore` и `USAGE` схемы `public`; право `CREATE` на схему отсутствует.
Для runtime-роли подтверждены права `SELECT`, `INSERT`, `UPDATE`, `DELETE` на
таблицах `Musicians`, `Sales`, `Ensembles`, `Users`, `Discs`, `Compositions`.
В правилах PostgreSQL для удалённого подключения используется адрес приложения
`192.168.56.10` и `scram-sha-256`.

## Автозапуск после перезагрузки

Обе ВМ перезапущены. После запуска `musicstore-api`, PostgreSQL и UFW активны;
службы приложения, БД и UFW включены при старте системы. С `MusicStore-App`
после перезагрузки проверен ответ API и TCP-доступ к `192.168.56.11:5432`.
