# ЛР 6. Continuous Delivery

## Схема доставки

GitHub Actions запускает обязательные проверки ЛР 5 на каждом push в `lab6/cd` и после их успеха публикует образ `ghcr.io/akng332/devops:sha-<полный SHA>`. Отдельная учётная запись `musicstore-deploy` на `MusicStore-App` раз в три минуты читает **последний** push-run этой ветки через GitHub API. Она принимает только завершённый успешный run, сверяет SHA скачанной ветки с run и запускает образ с тем же SHA. Неуспешный и ещё выполняющийся run не вызывают доставку. Pull request не вызывает публикацию и доставку.

Это pull-модель CD: ВМ сама забирает подтверждённый CI релиз из реестра. Сборки на ВМ нет. Такая схема нужна, потому что учебная ВМ находится только в Host-only сети `192.168.56.0/24` и недоступна GitHub-hosted runner напрямую.

Staging расположен на `MusicStore-App` отдельно от приложения ЛР 2–4: собственный проект Compose `musicstore-staging`, собственный том PostgreSQL и порт `192.168.56.10:18080`. Конфигурация, SQL-миграции и файлы секретов расположены на сервере вне образа. Секреты не сохраняются в Git.

## Проверка релиза и откат

`deploy/staging/deploy.sh` берёт блокировку `flock`, проверяет формат SHA-тега, скачивает образ из GHCR и запускает staging без сборки. Затем проверяет состояние контейнера, `/api/health`, `/version` (должен совпадать с SHA образа) и пользовательский сценарий чтения каталога `/api/discs`. Только после этого тег записывается в `.last-good-image`. При ошибке восстанавливается прежний образ; сбойный тег запоминается в `.failed-image`, чтобы планировщик не повторял его постоянно. База не удаляется при откате, поэтому несовместимые миграции требуют отдельного плана восстановления данных.

Ручной выпуск конкретного тега: `bash /opt/musicstore-staging/deploy.sh ghcr.io/akng332/devops:sha-<полный SHA>`. Ручной откат: запустить эту команду с предыдущим успешным тегом из журнала выпусков. Тест неуспешной smoke-проверки: `SMOKE_PATH=/api/missing bash /opt/musicstore-staging/deploy.sh <новый SHA-тег>`; скрипт должен завершиться ошибкой и вернуть предыдущий образ.

## Подтверждение

Отчёт и скриншоты хранятся локально в папке `Готовая лаба/ЛР6 - Continuous Delivery`. Журнал CI подтверждает проверку и публикацию, Docker Compose показывает отдельное окружение, запросы к API подтверждают здоровье, версию и каталог, а журнал развёртывания показывает неуспешный релиз и откат.
